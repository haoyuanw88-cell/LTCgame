# 樂齡認知遊戲 Android 發布與更新流程

## 正式商業發布方式

1. Unity 產生 Android App Bundle（`.aab`）。
2. 上傳至 Google Play Console 的「內部測試」軌道。
3. 測試通過後，依序推送至封閉測試、正式版。
4. 每次程式更新都提高 `versionCode`，並更新使用者看得到的版本號。
5. Google Play 只傳送裝置需要的差異內容，使用者由商店安全更新，不直接在遊戲內安裝不明 APK。

## 建議版本節奏

- 修正錯誤：1.0.0 → 1.0.1
- 新增功能或遊戲：1.0.0 → 1.1.0
- 大型架構更新：1.x → 2.0.0
- 正式發布前先經過：開發版 → 內部測試 → 小範圍測試 → 全量發布

## 封包與回復機制

- 每次保留上一個可正常運作的 AAB、對應 Git 標籤與更新說明。
- 正式版使用固定的 Android 簽署金鑰；金鑰需離線備份且不可提交到 GitHub。
- 發生嚴重問題時，停止分階段發布，修正後增加 `versionCode` 再上傳。
- APK 僅供開發測試與模擬器安裝；對外版本以 Google Play AAB 為主。

## 未來的小型內容更新

若未來要只更新圖片、音效或關卡，可導入 Unity Addressables，將遠端內容放到 CDN。程式碼變更仍必須重新建立並發布 AAB，不能用素材封包取代應用程式安全更新。
